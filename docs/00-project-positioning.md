# 00. 项目定位

## 一句话定义

RelayHub 是一个多 Agent 协作控制平面：它不负责替模型推理，而是负责让多个 Agent 在同一个任务里可靠地执行、交接、审查和留下可追溯记录。

## 要解决的问题

同时使用 Claude Code、Codex 或其他 Agent CLI 时，用户通常需要手动完成这些工作：

1. 在多个窗口之间复制任务背景和中间结果。
2. 判断现在该由哪个 Agent 接手。
3. 追踪 Agent 是否仍在运行、失败还是已经完成。
4. 组织“实现者”和“审查者”的协作流程。
5. 保存关键决策，避免下一次任务重新解释上下文。

RelayHub 将这些职责收敛到一个平台中。

## 目标用户

- 同时使用多个 AI 编程 Agent 的个人开发者。
- 想把“生成代码”升级为“可管理开发流程”的小团队。
- 希望研究 Agent Runtime、任务编排和可观测性的工程师。

## 简历定位

推荐定位为：

> 独立设计并实现的多 Agent 协作与任务编排平台，重点解决异构 Agent 接入、异步任务状态管理、实时事件流、Agent 间结构化交接和失败恢复问题。

它最适合支撑以下岗位方向：

- AI 应用后端 / AI Infra 初阶岗位
- Node.js / TypeScript 后端岗位
- 全栈工程师岗位
- Agent 平台或开发者工具岗位

## 核心技术亮点

### 1. 异构 Agent 适配

不同 Agent 的启动方式、事件格式和会话恢复机制不同。平台通过统一 `AgentAdapter` 接口把差异隔离在边界层，对上层只暴露统一事件。

### 2. 显式任务状态机

任务、执行和交接拥有清晰状态，不用“是否收到最后一条文本”猜测完成情况。状态变化必须来自受控命令或真实执行事件。

### 3. 异步队列与并发控制

同一 Agent 槽位串行、不同 Agent 可并行；支持取消、超时、重试以及进程异常后的状态收敛。

### 4. 实时事件流

前端通过 WebSocket 订阅任务房间，实时展示 Agent 文本、工具调用、状态变化和交接过程；断线后可依据序号补拉事件。

### 5. 可追溯协作

每次执行都保存输入、输出、父子关系、状态迁移与错误原因。Review 不是一段普通聊天，而是一个有输入和结论的结构化步骤。

## 项目边界

### MVP 必须实现

- 一个 Web 操作台。
- 至少两个 Agent Adapter，其中一个可使用 Mock Adapter 保证演示稳定。
- 创建任务并选择执行 Agent。
- 流式查看执行事件。
- Agent A 向 Agent B 发起结构化交接。
- Reviewer 输出结构化审查结论。
- 取消、失败、重试和审计时间线。

### 第二阶段再实现

- 从历史任务中检索共享记忆。
- 可配置工作流模板。
- Token / 成本统计。
- 多用户与团队权限。
- 远程 A2A 协议接入。

### 明确不做

- 不复刻 Clowder AI 的人格、陪伴、游戏、桌面端和外部 IM 生态。
- 不在 MVP 中实现复杂 RAG、向量数据库或自动知识治理。
- 不同时支持所有 Agent CLI。
- 不为了“像大厂架构”提前拆成大量微服务。

## 成功标准

项目不是以代码量衡量，而是满足以下标准：

1. 新用户能在 3 分钟内完成一次多 Agent 协作演示。
2. 任意一次运行都能从数据库还原其状态变化和 Agent 交接链。
3. Agent 进程失败或浏览器断线时，任务状态不会永久停留在错误状态。
4. 核心状态机、幂等和 Adapter 转换有自动化测试。
5. 面试时能解释每个组件为什么存在，以及为什么暂时没有使用更复杂方案。
