# ADR-001：采用独立 clean-room 实现与 MVP 范围

- 状态：Accepted
- 日期：2026-08-06

## 背景

RelayHub 位于 Clowder AI 仓库内，目的是通过研究成熟项目来完成一个适合作为个人简历作品的多 Agent 协作平台。如果直接复制原项目代码，既无法证明独立设计能力，也会继承远超个人项目需要的复杂度。

## 决策

1. 所有 RelayHub 文档、代码、测试和运行文件都放在 `relay-hub/` 内。
2. 原项目仅用于理解问题、观察设计模式和验证风险点。
3. RelayHub 使用独立的领域语言：Workspace、Task、Run、Handoff、Review。
4. MVP 只实现任务编排、Agent Adapter、实时事件、结构化交接、Review 和失败恢复。
5. 使用模块化单体 API + 独立 Worker，不复制原项目包结构。
6. 不复制原项目的函数、类、测试或 UI。

## 结果

正面影响：

- 面试时可以清楚区分“参考了什么”和“自己设计了什么”。
- 项目规模可以控制在个人可交付范围内。
- 架构与代码更容易围绕一条演示主线优化。

代价：

- 需要重新实现已有基础设施。
- 第一版能力数量明显少于参考项目。
- 必须持续维护需求、实现和面试表述之间的一致性。

## 后续约束

若未来要引入 Clowder AI 中的新能力，必须先补充 ADR 或更新需求文档，说明用户价值、MVP 必要性以及独立实现方案。
